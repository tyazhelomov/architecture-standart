### <a name="_qmphm5d6rvi3"></a>**Решение**
Для MVP будет достаточно UC1, т.к. потребуется меньшее количество изменений в системе, которое приведет систему в соответствование требованиям.
Так же, открытие счета через интернет банк будет невозможно для новых пользователей, которые еще не стали клиентами банка.
В этом случае, пользователю также будет необходимо сделать обращение через сайт и прийти в банк для загрузки документов.
В связи с этим есть смысл начать MVP с реализации подачи заявки на открытие депозита через сайт.
На финальных этапах реализации будет возможность начать имплементацию открытия депозитов через интернет-банк,
т.к. компоненты системы частично будут готовы для получения трафика и процесс реализации ускорится на 50%.
Также будет возможность перед реализацией протестировать флоу открытия депозитов через сайт и получить обратную связь, которую можно учесть при 
реализации UC2.

Также будет необходимость поднять дополнительный ЦОД в режиме Active, чтобы распределить пользовательский трафик и повысить отказоустойчивость
в соответствии с требованиями. Дополнительно, необходимо вычленить процесс подачи заявок в отдельный микросервис.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
В качестве альтернативы можно рассмотреть запуск новой логики подачи заявок без изменения текущего процесса смены ЦОД и без выноса в отдельный микросервис.
Это поможет запустить новый процесс быстрее на 28%, однако, в среднесрочной перспективе это окажет негативное влияние при сбоях и\или увеличения трафика.
Также, это усложнит доставку новых фич бизнесу и усложнит обслуживание этого процесса.

**Недостатки, ограничения, риски**
Доработки в системе должны быть реализованы с помощью технологий, которые в данный момент используются в компании. Это позволит избежать bottleneck в ресурсе разработчиков.
Также, учитывая что процесс взаимодействия между интернет банком и АБС должен быть асинхронным, необходимо принять решение по использованию инструмента для организации очереди. Исходя из вводных, необходимо составить новое ADR для выбора подходящего инструмента или внесение изменений в платформу, т.к. текущая версия платформы не поддерживается использование Kafka.
