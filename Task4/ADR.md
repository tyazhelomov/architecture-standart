### <a name="_qmphm5d6rvi3"></a>**Решение**
В ходе переговоров партнерский кол-центр подтвердил возможность использования системы банка для просмотра актуальных ставок. В связи с этим было принято решение разработать отдельную админку для кол-центра для просмотра актуальных ставок по депозитам. Бекенд админки будет обращаться к АБС с ограниченным доступом для получения актуальных ставок по депозитам. Т.к. фронтенд админки будет доступен из интернета для партнерского и внутреннего кол-центров имеет смысл использовать IAM Keycloak для доступа в систему. Админка будет позволять фильтровать и подбирать ставки в зависимости от истории и пожеланий клиента. Система будет приоритетным выбором, т.к. пользователи могут в реальном времени получать актуальную информацию о ставках, не дожидаясь новых файлов. Т.к. пользователей будет разумное количество в пределах 300 аккаунтов, ожидается, что RPS будет не более 1. Тем не менее, необходимо добавить кеширование запросов, а также настроить метрики и алерты, в случае увеличения трафика.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
В качестве альтернативы можно рассмотреть передачу файлов для кол-центра. Это более быстрое решение, однако это может ввести в заблуждение как операторов кол-центра, так и потенциальных клиентов банка. Файлы могут не отправиться, операторы могут открыть старые файлы и т.д. С помощью админки этого можно избежать.
Также рассматривалась возможность выдачи доступа напрямую в систему банка, однако этот вариант был отвергнут из-за потенциальных угроз утечек и юридических вопросов.

**Недостатки, ограничения, риски**
Доработки в системе должны быть реализованы с помощью технологий, которые в данный момент используются в компании. Это позволит избежать bottleneck в ресурсе разработчиков.
Также, необходимо использовать IAM Keycloak для получения доступа в систему, однако так как система будет развернута на ресурсах компании, риски снижаются, т.к. все данные пользователей будут храниться на серверах компании и поддерживаться разработкой компании.
